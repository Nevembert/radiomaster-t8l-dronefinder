# RadioMaster T8L DroneFinder 1.0

Неофициальная прошивка RadioMaster T8L с поиском связанного дрона по силе
сигнала: четыре светодиода показывают уровень, а писк учащается при его росте.
Двойное нажатие **M** включает и выключает поиск.

**[Скачать версию 1.0](https://github.com/Nevembert/radiomaster-t8l-dronefinder/releases/tag/v1.0.0)** · **[Установка и проверка](FIRST_TEST_RU.md)**

Основа — **T8L Controller v1.7**, исходная конфигурация — **ELRS 3.6.2 CE_LBT**.
Прошивается контроллер пульта; прошивка внутреннего ELRS-модуля не заменяется.
Это индикатор силы сигнала собственного связанного приёмника, не сканер чужих
дронов. Приёмнику нужны питание и работающая телеметрия.

Версия проекта **1.0**, тег **v1.0.0**. Образ совпадает побайтно с последней
аудиосборкой, ранее обозначенной 0.7. Штатный WebUI может продолжать показывать
базовую версию контроллера v1.7: её строка внутри прошивки не изменена.

**Статус проверки:** установка предыдущей сборки 0.6 и штатный вход/выход из
загрузчика подтверждены пользователем. Звуковая сборка прошла программные
проверки; её аппаратная и полётная проверка не подтверждены. Номер 1.0
обозначает выпуск проекта, а не сертификацию для полётов.

## Что изменилось

В режиме поиска добавлен штатный короткий писк. Интервал запросов плавно
меняется по сглаженному RSSI от 1600 мс при -110 dBm и ниже до 200 мс
при -20 dBm и выше. Это не шкала расстояния: тело, стены, ориентация антенн
и мощность телеметрии влияют на сигнал. Выше уровень сигнала — чаще писк.

| RSSI | Интервал запросов писка |
|---|---|
| -110 dBm | 1,60 с |
| -90 dBm | 1,29 с |
| -70 dBm | 0,98 с |
| -50 dBm | 0,67 с |
| -35 dBm | 0,43 с |
| -20 dBm | 0,20 с |

Используется та же короткая звуковая последовательность, что и у штатной
прошивки: включение и выключение через её очередь. Громкость берётся из
настроек T8L. Длительность аппаратного писка отдельно не измерена.
При занятом звуковом механизме очередной поисковый писк пропускается,
поэтому реальные интервалы могут быть длиннее таблицы. Штатные сообщения
не удаляются и не переставляются. Уже добавленный короткий писк может
доиграть после выхода; новое штатное сообщение может подождать его окончания.

Без действительного свежего сигнала поисковых писков нет. Штатное предупреждение
потери связи остаётся. Поиск также молчит при зарядке/USB, низкой батарее,
в системных режимах и при CH5 выше 1500. Последнее — соглашение ELRS AUX1,
а не подтверждение отключённых моторов при произвольной настройке дрона.

## Управление

Два коротких нажатия M включают поиск, ещё два — выключают. Нажатия до
250 мс, промежуток до 350 мс. Долгое M остаётся штатным биндингом.
После выключения питания поиск не сохраняется. Четыре LED показывают уровень сигнала:
границы -90/-70/-35 dBm, сглаживание 1/4 и гистерезис 3 dB.
Нет свежих данных 1500 мс — чередуются внешняя и внутренняя пары LED.
Это таймаут полученных отчётов; полная задержка потери RF может быть больше.

## Файлы для установки и возврата

- `build/T8L_v17_DroneFinder_1.0.bin` — единственный новый полный BIN.
- `recovery/T8L_v17_DroneFinder_0.6_BENCH_UNVALIDATED.bin` — предыдущий образ 0.6,
  об установке которого сообщил пользователь.
- `recovery/T8L-V1_7updata.bin` — неизменённая официальная версия 1.7.
- `build/module.bin` — создаётся при сборке; это модуль разработчика, НЕ прошивка для загрузки.

Наличие файлов возврата не гарантирует восстановление, если новая программа
не запускается и загрузчик недоступен. Независимый аварийный вход без разборки
не установлен. Настройки пользователя в этих BIN не сохранены.

Порядок обновления и теста: [FIRST_TEST_RU.md](FIRST_TEST_RU.md).
Произвольные WAV/MP3 и новая голосовая озвучка не добавлены.

## Проверки и ограничения

Пройдены 7 native-наборов ASan/UBSan, 2 проверки анализатора, 9 статических
проверок образа и 8 ARM/Thumb-сценариев. В эмуляторе выполняется только наш
модуль; 6 штатных функций заменены заглушками. Реальная очередь, PWM,
прерывания и звуковая длительность так не проверены.

Модуль 2300 байт; состояние 64 байта внутри прежнего резерва 128 байт.
Полный BIN 96844 байта. Максимальная наблюдённая глубина собственного стека
в эмуляторе — 144 байта, без штатного кода и IRQ. Новых мест перехвата нет:
те же 22 правки исходного образа, таблица прерываний не меняется.

Для штатного писка нужны два узла по 24 байта с заголовками. Перед вызовом
проверяются пустая очередь, выключенный PWM, отсутствие активного звукового
задания и место для двух узлов в свободной памяти. Проверка ограничена
64 узлами и выполняется вместе с добавлением писка при сохранённом PRIMASK.
Неверные указатели, цикл списка, нехватка памяти — писк пропускается.
Остаточный запас памяти и время критической секции на пульте ещё не измерены.

Сборка всегда выполняется из официального образа 1.7 с проверкой SHA-256,
не поверх модифицированной 0.6. Все исходники и тесты включены в архив.

```sh
python tools/build_candidate.py --firmware recovery/T8L-V1_7updata.bin
python tests/run_tests.py --firmware recovery/T8L-V1_7updata.bin
python tests/test_candidate.py recovery/T8L-V1_7updata.bin build
python tests/test_arm_module.py build
```

Нужны ARM GNU Toolchain (эталонная сборка: GCC 12.2.1), Python 3,
C-компилятор с ASan/UBSan и `pip install unicorn==2.1.4` для ARM-тестов. Сборщик не получает
доступ к устройству и не прошивает его. `bench/` содержит диагностическую страницу для чтения USB-телеметрии.
Версия формата её отчётов 0.6 независима от версии прошивки 1.0.
Тесты используют искусственные данные. Личные журналы испытаний в репозиторий
и установочный архив не включены.

```sh
node tests/test_bench.cjs
node tests/test_bench_ui.cjs
python tools/package_release.py
```

Последняя команда проверяет контрольные суммы всех публикуемых файлов и
создаёт установочный ZIP в `dist/`. [Подробности реализации](RESEARCH.md),
[результаты проверок](build/test-results.json), [происхождение файлов](NOTICE.md).
